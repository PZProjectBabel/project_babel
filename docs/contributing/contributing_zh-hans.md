## 2. 我可以如何贡献？

你可以根据自己的兴趣和技能，选择一种或多种方式参与：

- 提供目标语言的翻译规则
- 提供目标语言的翻译术语词典
- 改进系统的提示词
- 提供人工校对后的翻译文本语料
- 改进流水线模块（.NET）与自动化脚本
- 报告问题、提出改进建议（在 Issues 中说明）
- 提供资金支持LLM的调用

下面对主要贡献场景做一些说明。

---

## 3. 提供翻译规则、术语词典、改进系统提示词

流水线的提示词模板位于 `src/prompt_templates/`，结构如下：

- `system_prompt_translate_engine.txt`：全局翻译引擎系统提示词（所有语言共用）；
- `<语言代码>/translation_dictionary_<语言代码>.json`：该语言的术语词典；
- `<语言代码>/translation_schema_<语言代码>.md`：该语言的翻译规则与风格约束。

贡献步骤：

1. 在 `src/prompt_templates/` 下为你的语言创建子目录，添加术语词典与翻译规则文件；
2. 如需调整全局翻译行为，修改 `system_prompt_translate_engine.txt`（注意影响所有语言）；
3. 本地测试确认效果；
4. 提交 PR。

---

## 4. 提供人工校对语料

如果你是翻译模组制作者，并且愿意提供你的翻译语料作为 LLM 翻译参考，请在 Issue 中发起申请。你需要提供以下资料：

- 你的翻译模组的 Mod ID 以及翻译的目标语言；
- 你的翻译模组的后台页面截图，以证明你是模组作者；
- 在 Issue 中明确表示你愿意提供翻译语料；
- 如有特殊情况（特殊授权等），请一并说明；
- 请确保你提供的语料具有较高的质量。

在你的授权下，项目会将你的模组列入 `config/ref_translation_mods.json` 参考翻译模组列表中，流水线会自动同步你的翻译文本作为 RAG 参考语料。

## 5. 流水线与工具开发贡献

本项目的自动化分为两部分：

**流水线模块（`src/`，C# / .NET 10）**：包含 15 个按序执行的模块，外加 2 个独立模块（`WorkshopMonitor` 模组发现器、`DocGenerator` 文档生成器），负责从 SteamCMD 初始化、模组下载、文本提取、内容审查、Embedding 计算、RAG 检索到 LLM 翻译与最终输出的完整流程。详见 [技术参考](../technical_reference/technical_reference_zh-hans.md)。

**辅助脚本（.github/）**：用于github的自动化。

若你希望：

* 修复现有流水线模块或脚本中的 Bug；
* 为流水线添加新功能或新模块；
* 优化性能或代码结构；
* 改进 prompt 模板或 RAG 策略；

可以按如下步骤：

1. Fork 本仓库并克隆到本地；
2. 基于最新分支创建新分支；
3. 在对应目录中修改或新增文件：
   - 流水线模块修改 → `src/<模块名>/`；
   - CI 工作流修改 → `.github/workflows/`；
   - Prompt 模板修改 → `src/prompt_templates/`；
4. 提交前请尽量：

   * 保持原有代码风格；
   * 添加必要的注释；
   * 如有条件，附上简单的测试或使用说明；
5. 通过 PR 提交修改，并在描述中说明：

   * 改动目的；
   * 可能影响的目录 / 模块 / 脚本；
   * 是否涉及破坏性变更。

## 8. 资金支持

项目运行中，由于新增模组、旧模组更新文本内容等，需要持续调用LLM API进行翻译。而为了约束LLM行为，除了基础的模组文本外，还需要提供大量的提示词内容（包括基础提示词、翻译规则、术语表、输入输出约束、语义查询结果等），这些内容会消耗远超原始文本的词元。因此，项目需要资金的支持。

如果你愿意提供资金支持，请联系项目维护者。非常感谢！
