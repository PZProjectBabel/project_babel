## 3. 翻訳ルール、用語辞書の提供、システムプロンプトの改善

パイプラインのプロンプトテンプレートは `src/prompt_templates/` にあり、構成は以下の通りです：

- `system_prompt_translate_engine.txt`：グローバル翻訳エンジンシステムプロンプト（全言語共通）；
- `<言語コード>/translation_dictionary_<言語コード>.json`：その言語の用語辞書；
- `<言語コード>/translation_schema_<言語コード>.md`：その言語の翻訳ルールとスタイル制約。

貢献の手順：

1. `src/prompt_templates/` 以下にあなたの言語用のサブディレクトリを作成し、用語辞書と翻訳ルールファイルを追加します；
2. グローバルな翻訳動作を調整する場合は、`system_prompt_translate_engine.txt` を修正します（すべての言語に影響することに注意）；
3. ローカルでテストして効果を確認します。
4. PR を提出します。

## 4. 人手による校正済みコーパスの提供

あなたが翻訳Mod製作者で、LLM翻訳の参考として翻訳コーパスを提供していただける場合は、Issueで申請してください。以下の情報が必要です。

- 翻訳ModのMod IDと翻訳対象言語
- 翻訳Modの管理画面のスクリーンショット（Mod製作者であることの証明）
- Issueで翻訳コーパスを提供する意思を明確に表明すること
- 特殊な事情（特別な許諾など）がある場合は、その旨も説明してください。
- 提供するコーパスは高い品質であることを確認してください。

あなたの許諾のもと、プロジェクトはあなたのModを `config/ref_translation_mods.json` の参考翻訳Modリストに追加し、パイプラインが自動的に翻訳テキストをRAG参照コーパスとして同期します。

## 5. パイプラインとツール開発への貢献

本プロジェクトの自動化は2つの部分に分かれています。

**パイプラインモジュール（`src/`、C# / .NET 10）**：15個の順次実行モジュールから構成され、SteamCMD初期化、Modダウンロード、テキスト抽出、内容審査、Embedding計算、RAG検索からLLM翻訳、最終出力までの完全なフローを担当します。詳細は [技術リファレンス](../technical_reference/technical_reference_ja.md) を参照してください。

**補助スクリプト（.github/）**：GitHubの自動化に使用されます。

あなたが希望する場合：

* 既存のパイプラインモジュールやスクリプトのバグ修正
* パイプラインへの新機能・新モジュールの追加
* パフォーマンスやコード構造の最適化
* promptテンプレートやRAG戦略の改善

以下の手順で行えます。

1. このリポジトリをForkしてローカルにクローンします。
2. 最新のブランチから新しいブランチを作成します。
3. 対応するディレクトリでファイルを修正または追加します。
- パイプラインモジュールの修正 → `src/<モジュール名>/`
- スクリプトの修正 → `scripts/`
- Promptテンプレートの修正 → `src/prompt_templates/`
4. 提出前には以下の点に努めてください。

* 既存のコードスタイルを維持する
* 必要なコメントを追加する
* 可能であれば簡単なテストや使用説明を添付する
5. PRを通じて修正を提出し、説明欄で以下を記述してください：

* 変更の目的；
* 影響を受ける可能性のあるディレクトリ/モジュール/スクリプト；
* 破壊的な変更を含むかどうか。

## 8. 資金支援

プロジェクト運営中、新しいModの追加や既存Modのテキスト更新などにより、継続的にLLM APIを呼び出して翻訳する必要があります。また、LLMの動作を制約するために、基本的なModテキストに加えて、多数のプロンプト内容（基本プロンプト、翻訳ルール、用語集、入出力制約、セマンティック検索結果など）を提供する必要があり、これらの内容は元のテキストをはるかに超えるトークンを消費します。そのため、プロジェクトには資金の支援が必要です。

資金支援を提供していただける場合は、プロジェクトメンテナーにご連絡ください。大変感謝します！
