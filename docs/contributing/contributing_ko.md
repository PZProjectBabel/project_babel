**Project Babel — Project Zomboid 모드 LLM 자동 번역 프로젝트**에 기여해 주셔서 대단히 감사합니다! 버그 수정, 기능 추가, 프롬프트 템플릿 작성, 참조 번역 제공 등 모든 기여를 환영합니다!

LLM API를 호출하여 번역하려면 토큰 비용이 발생합니다. 프로젝트가 장기적으로 안정적으로 운영될 수 있도록 여러분의 아낌없는 지원을 부탁드립니다!

> ⚠️ **중요 안내:**
> 이 저장소에 어떤 내용이든 제출하기 전에 반드시 ㈜저작권 및 라이선스 약정㈜ 섹션을 읽고 이해하시기 바랍니다.
> 제출 및 병합되면 해당 라이선스 조항에 동의한 것으로 간주됩니다.

## 시작하기 전에

먼저 프로젝트 `README.md`를 읽고 다음 사항을 이해하세요:

- 본 프로젝트의 전체 목표와 현재 상태;
- 일반 플레이어가 이 프로젝트를 어떻게 사용하는지 (직접 테스트용);
- 프로젝트 기술 세부 사항.

## 어떻게 기여할 수 있나요?

관심사와 기술에 따라 다음 중 하나 이상의 방법으로 참여할 수 있습니다:

- 대상 언어의 번역 규칙 제공
- 대상 언어의 용어 사전 제공
- 시스템 프롬프트 개선
- 수동으로 교정된 번역 말뭉치 제공
- 파이프라인 모듈(.NET) 및 자동화 스크립트 개선
- Issue를 통한 문제 보고 및 개선 제안
- LLM API 호출을 위한 재정 지원

아래에서 주요 기여 시나리오에 대해 설명합니다.

## 번역 규칙, 용어 사전 제공 및 시스템 프롬프트 개선

파이프라인의 프롬프트 템플릿은 `src/prompt_templates/`에 있으며, 구조는 다음과 같습니다:

- `system_prompt_translate_engine.txt`: 전역 번역 엔진 시스템 프롬프트 (모든 언어 공용);
- `<언어_코드>/translation_dictionary_<언어_코드>.json`: 해당 언어의 용어 사전;
- `<언어_코드>/translation_schema_<언어_코드>.md`: 해당 언어의 번역 규칙 및 스타일 제약.

기여 절차:

1. `src/prompt_templates/` 아래에 언어별 하위 디렉터리를 만들고 용어 사전과 번역 규칙 파일을 추가합니다;
2. 전역 번역 동작을 조정해야 하는 경우 `system_prompt_translate_engine.txt`를 수정합니다 (모든 언어에 영향을 미침에 유의);
3. 로컬에서 테스트하여 효과를 확인합니다;
4. PR을 제출합니다.

## 수동 교정 말뭉치 제공

번역 모드 제작자로서 LLM 번역 참조용으로 번역 말뭉치를 제공할 의향이 있으시다면 Issue로 신청해 주세요. 다음 정보가 필요합니다:

- 번역 모드의 Mod ID 및 대상 언어;
- 모드 제작자임을 증명할 수 있는 번역 모드의 백엔드 페이지 스크린샷;
- Issue에서 번역 말뭉치를 기꺼이 제공한다는 명시적 의사 표시;
- 특별한 상황 (특별 라이선스 등)이 있다면 함께 설명;
- 제공하는 말뭉치의 높은 품질을 확인해 주세요.

귀하의 승인 하에, 프로젝트는 귀하의 모드를 `config/ref_translation_mods.json` 참조 번역 모드 목록에 추가하고, 파이프라인이 자동으로 번역 텍스트를 RAG 참조 말뭉치로 동기화합니다.

## 파이프라인 및 도구 개발 기여

본 프로젝트의 자동화는 두 부분으로 나뉩니다:

**파이프라인 모듈 (`src/`, C# / .NET 10)**: 15개의 순차 실행 모듈로 구성되어 모드 다운로드, 텍스트 추출, 콘텐츠 심사, Embedding 계산, RAG 검색부터 LLM 번역 및 최종 출력까지의 완전한 워크플로를 담당합니다. 자세한 내용은 [기술 문서](../translation_entry_pipeline_zh-hans.md)를 참조하세요.

**보조 스크립트 (`.github/`)**: GitHub 자동화에 사용됩니다.

다음과 같은 작업을 원하신다면:

* 기존 파이프라인 모듈이나 스크립트의 버그 수정;
* 파이프라인에 새 기능이나 새 모듈 추가;
* 성능 또는 코드 구조 최적화;
* 프롬프트 템플릿 또는 RAG 전략 개선;

다음 단계에 따라 진행할 수 있습니다:

1. 이 저장소를 Fork하고 로컬에 클론합니다;
2. 최신 브랜치에서 새 브랜치를 만듭니다;
3. 해당 디렉터리에서 파일을 수정하거나 추가합니다:
   - 파이프라인 모듈 변경 → `src/<모듈명>/`;
   - 스크립트 변경 → `scripts/`;
   - 프롬프트 템플릿 변경 → `src/prompt_templates/`;
4. 제출 전에 가능한 한 다음을 지켜주세요:

   * 기존 코드 스타일 유지;
   * 필요한 주석 추가;
   * 가능하다면 간단한 테스트나 사용 설명을 첨부;
5. PR로 변경 사항을 제출하고 설명에 다음을 명시하세요:

   * 변경 목적;
   * 영향을 받을 수 있는 디렉터리 / 모듈 / 스크립트;
   * 파괴적 변경 여부.

### 1. 기본 원칙: 귀하는 저작권을 보유하면서 프로젝트에 사용을 허가합니다

* 귀하가 창작한 콘텐츠(번역, 이미지, 스크립트/프로그램 등)에 대한 저작권은 여전히 귀하에게 있습니다;
* 그러나 이러한 콘텐츠를 본 프로젝트에 제출하고 채택(병합)된 후에는,
  귀하는 본 프로젝트가 채택한 오픈소스/공유 라이선스 계약에 따라 타인이 이러한 콘텐츠를 사용할 수 있도록 허가한 것에 동의합니다.

이는 다음을 의미합니다:

* 귀하는 **여전히** 다른 곳에서 자신의 작품을 계속 사용하고 전시할 수 있습니다;
* 그러나 기여가 병합된 후에는 본 프로젝트나 이미 합법적으로 작품을 취득한 다른 사용자에게 ㈜허가 철회㈜나 ㈜이전 버전 삭제㈜를 요구할 수 **없습니다**.

## 재정 지원

프로젝트 운영 중에는 새로운 모드 추가, 기존 모드의 텍스트 업데이트 등으로 인해 지속적으로 LLM API를 호출하여 번역해야 합니다. LLM의 동작을 제약하기 위해 기본 모드 텍스트 외에도 대량의 프롬프트 콘텐츠(기본 프롬프트, 번역 규칙, 용어표, 입출력 제약, 시맨틱 검색 결과 등)가 필요하며, 이는 원본 텍스트보다 훨씬 많은 토큰을 소비합니다. 따라서 프로젝트에는 재정 지원이 필요합니다.

재정 지원을 원하시면 프로젝트 유지관리자에게 연락해 주세요. 대단히 감사합니다!
