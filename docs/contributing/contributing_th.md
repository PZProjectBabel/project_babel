## ฉันสามารถมีส่วนร่วมได้อย่างไร?

คุณสามารถเลือกหนึ่งหรือหลายวิธีในการเข้าร่วมตามความสนใจและทักษะของคุณ:

- ให้กฎการแปลสำหรับภาษาเป้าหมาย
- ให้พจนานุกรมคำศัพท์สำหรับภาษาเป้าหมาย
- ปรับปรุงพร้อมท์ของระบบ
- ให้คลังข้อความแปลที่ตรวจทานด้วยตนเอง
- ปรับปรุงโมดูลไปป์ไลน์ (.NET) และสคริปต์อัตโนมัติ
- รายงานปัญหาและเสนอการปรับปรุง (ผ่าน Issues)
- ให้การสนับสนุนทางการเงินสำหรับการเรียกใช้ LLM API

ด้านล่างนี้เป็นคำอธิบายสำหรับสถานการณ์การมีส่วนร่วมหลัก

## การให้กฎการแปล พจนานุกรมคำศัพท์ และการปรับปรุงพร้อมท์ของระบบ

เทมเพลตพร้อมท์ของไปป์ไลน์อยู่ใน `src/prompt_templates/` โดยมีโครงสร้างดังนี้:

- `system_prompt_translate_engine.txt`: พร้อมท์ระบบของเอนจินแปลส่วนกลาง (ใช้ร่วมกันทุกภาษา);
- `<รหัสภาษา>/translation_dictionary_<รหัสภาษา>.json`: พจนานุกรมคำศัพท์สำหรับภาษานั้น;
- `<รหัสภาษา>/translation_schema_<รหัสภาษา>.md`: กฎการแปลและข้อจำกัดด้านรูปแบบสำหรับภาษานั้น.

ขั้นตอนการมีส่วนร่วม:

1. สร้างไดเรกทอรีย่อยภายใต้ `src/prompt_templates/` สำหรับภาษาของคุณ และเพิ่มไฟล์พจนานุกรมและกฎ;
2. หากคุณต้องการปรับพฤติกรรมการแปลส่วนกลาง ให้แก้ไข `system_prompt_translate_engine.txt` (หมายเหตุ: สิ่งนี้มีผลต่อทุกภาษา);
3. ทดสอบในเครื่องเพื่อยืนยันผลลัพธ์;
4. ส่ง PR.

## การให้คลังข้อความที่ตรวจทานด้วยตนเอง

หากคุณเป็นผู้เขียนม็อดแปลและยินดีที่จะให้คลังข้อความแปลของคุณเป็นข้อมูลอ้างอิงสำหรับ LLM โปรดส่งคำขอผ่าน Issue คุณต้องให้ข้อมูลต่อไปนี้:

- Mod ID ของม็อดแปลของคุณและภาษาเป้าหมาย;
- ภาพหน้าจอของหน้าผู้ดูแลม็อดแปลของคุณเพื่อพิสูจน์ว่าคุณเป็นผู้เขียน;
- ข้อความที่ชัดเจนใน Issue ว่าคุณยินดีที่จะให้คลังข้อความแปล;
- หากมีสถานการณ์พิเศษ (การอนุญาตพิเศษ ฯลฯ) โปรดอธิบาย;
- โปรดตรวจสอบให้แน่ใจว่าคลังข้อความที่คุณให้มีคุณภาพสูง.

ด้วยการอนุญาตของคุณ โครงการจะเพิ่มม็อดของคุณลงในรายการม็อดแปลอ้างอิง `config/ref_translation_mods.json` และไปป์ไลน์จะซิงค์ข้อความแปลของคุณเป็นคลังอ้างอิง RAG โดยอัตโนมัติ.

## การมีส่วนร่วมในการพัฒนาไปป์ไลน์และเครื่องมือ

ระบบอัตโนมัติในโครงการนี้แบ่งออกเป็นสองส่วน:

**โมดูลไปป์ไลน์ (`src/`, C# / .NET 10)**: ประกอบด้วย 15 โมดูลที่ทำงานตามลำดับ รับผิดชอบเวิร์กโฟลว์ทั้งหมดตั้งแต่การดาวน์โหลดม็อด การแยกข้อความ การตรวจสอบเนื้อหา การคำนวณ Embedding การค้นคืน RAG ไปจนถึงการแปล LLM และผลลัพธ์สุดท้าย ดู [เอกสารทางเทคนิค](../translation_entry_pipeline_zh-hans.md) สำหรับรายละเอียด.

**สคริปต์เสริม (`.github/`)**: ใช้สำหรับระบบอัตโนมัติของ GitHub.

หากคุณต้องการ:

* แก้ไขข้อบกพร่องในโมดูลไปป์ไลน์หรือสคริปต์ที่มีอยู่;
* เพิ่มฟีเจอร์หรือโมดูลใหม่ให้กับไปป์ไลน์;
* เพิ่มประสิทธิภาพหรือโครงสร้างโค้ด;
* ปรับปรุงเทมเพลตพร้อมท์หรือกลยุทธ์ RAG;

คุณสามารถทำตามขั้นตอนเหล่านี้:

1. Fork ที่เก็บนี้และโคลนในเครื่อง;
2. สร้าง branch ใหม่จาก branch ล่าสุด;
3. แก้ไขหรือเพิ่มไฟล์ในไดเรกทอรีที่เกี่ยวข้อง:
   - การเปลี่ยนแปลงโมดูลไปป์ไลน์ → `src/<ชื่อโมดูล>/`;
   - การเปลี่ยนแปลงสคริปต์ → `scripts/`;
   - การเปลี่ยนแปลงเทมเพลตพร้อมท์ → `src/prompt_templates/`;
4. ก่อนส่ง พยายาม:

   * รักษารูปแบบโค้ดที่มีอยู่;
   * เพิ่มความคิดเห็นที่จำเป็น;
   * หากเป็นไปได้ แนบการทดสอบง่ายๆ หรือคำแนะนำการใช้งาน;
5. ส่งการเปลี่ยนแปลงผ่าน PR และอธิบายในคำอธิบาย:

   * วัตถุประสงค์ของการเปลี่ยนแปลง;
   * ไดเรกทอรี / โมดูล / สคริปต์ที่อาจได้รับผลกระทบ;
   * เกี่ยวข้องกับการเปลี่ยนแปลงที่กระทบความเข้ากันได้หรือไม่.

## ลิขสิทธิ์และการอนุญาต

> **ข้อเตือนใจ:**
> ข้อกำหนดลิขสิทธิ์และการอนุญาตถูกออกแบบมาเพื่อปกป้องสิทธิและผลประโยชน์ที่ชอบธรรมของโครงการ ผู้เขียน ผู้มีส่วนร่วม และผู้เล่น และเพื่อหลีกเลี่ยงความเข้าใจผิดที่เกิดจาก "ข้อตกลงโดยปริยาย" หรือ "ข้อสันนิษฐานโดยค่าเริ่มต้น" โปรดอ่านอย่างละเอียด.
> ลิขสิทธิ์และการอนุญาตอยู่ภายใต้เนื้อหาในไฟล์ README.md; ส่วนนี้ให้เพียงคำอธิบายที่เข้าใจง่ายขึ้น.

### 1. หลักการพื้นฐาน: คุณรักษาลิขสิทธิ์ไว้ ในขณะที่อนุญาตให้โครงการใช้งานผลงานของคุณ

* คุณยังคงถือลิขสิทธิ์ในเนื้อหาที่คุณสร้างขึ้น (คำแปล รูปภาพ สคริปต์/โปรแกรม ฯลฯ);
* อย่างไรก็ตาม เมื่อเนื้อหานี้ถูกส่งไปยังโครงการนี้และได้รับการยอมรับ (ผสาน),
  คุณตกลงที่จะอนุญาตให้ผู้อื่นใช้เนื้อหานี้ภายใต้ใบอนุญาตโอเพนซอร์ส/แบ่งปันที่โครงการนี้ใช้.

นี่หมายความว่า:

* คุณ **ยังคงสามารถ** ใช้และแสดงผลงานของคุณในที่อื่นต่อไป;
* แต่คุณ **ไม่สามารถ** หลังจากที่ผลงานของคุณถูกผสาน เรียกร้องให้โครงการนี้หรือผู้ใช้รายอื่นที่ได้รับผลงานอย่างถูกกฎหมาย "เพิกถอนใบอนุญาต" หรือ "ลบเวอร์ชันประวัติ".

  * ไม่คัดลอกข้อความแปลหรือทรัพยากรศิลปะของบุคคลที่สามที่ไม่ได้รับอนุญาตโดยตรง;
  * เคารพสิทธิ์ของผู้เขียนต้นฉบับและผู้เขียนม็อด และไม่ทำการแจกจ่ายซ้ำที่ละเมิดลิขสิทธิ์.

## การสื่อสารและการทำงานร่วมกัน

หากคุณมี:

* คำถามเกี่ยวกับข้อกำหนดใบอนุญาต;
* ความไม่แน่ใจว่าเนื้อหาบางอย่างสามารถมีส่วนร่วมได้หรือไม่;
* ความต้องการที่จะอนุญาตผลงานของคุณในรูปแบบพิเศษ (เช่น ใช้ไม่เชิงพาณิชย์เท่านั้น แต่ไม่อนุญาตให้ดัดแปลง);

ยินดีติดต่อผู้ดูแลโครงการผ่าน:

* การส่ง Issue เพื่ออภิปราย;
* วิธีการติดต่อสาธารณะอื่นๆ ของผู้ดูแล.

เราจะพยายามอย่างเต็มที่ในการหาทางออกที่สมดุลระหว่างการพัฒนาโครงการที่ดีและเคารพสิทธิและผลประโยชน์ของทุกฝ่าย.

## การสนับสนุนทางการเงิน

ระหว่างการดำเนินโครงการ เนื่องจากการเพิ่มม็อดใหม่และการอัปเดตข้อความของม็อดที่มีอยู่ จำเป็นต้องเรียกใช้ LLM API อย่างต่อเนื่องเพื่อแปล เพื่อจำกัดพฤติกรรมของ LLM นอกจากข้อความม็อดพื้นฐานแล้ว ยังต้องใช้เนื้อหาพร้อมท์จำนวนมาก (รวมถึงพร้อมท์พื้นฐาน กฎการแปล ตารางคำศัพท์ ข้อจำกัดอินพุต/เอาต์พุต ผลการค้นหาเชิงความหมาย ฯลฯ) ซึ่งใช้โทเค็นมากกว่าข้อความต้นฉบับมาก ดังนั้นโครงการจึงต้องการการสนับสนุนทางการเงิน.

หากคุณต้องการให้การสนับสนุนทางการเงิน โปรดติดต่อผู้ดูแลโครงการ ขอบคุณมาก!
