## 我可以如何貢獻？

你可以根據自己的興趣和技能，選擇一種或多種方式參與：

- 提供目標語言的翻譯規則
- 提供目標語言的翻譯術語詞典
- 改進系統的提示詞
- 提供人工校對後的翻譯文字語料
- 改進管線模組（.NET）與自動化指令碼
- 回報問題、提出改進建議（在 Issues 中說明）
- 提供資金支援 LLM 的呼叫

下面對主要貢獻情境做一些說明。

---

## 提供翻譯規則、術語詞典、改進系統提示詞

管線的提示詞範本位於 `src/prompt_templates/`，結構如下：

- `system_prompt_translate_engine.txt`：全域翻譯引擎系統提示詞（所有語言共用）；
- `<語言代碼>/translation_dictionary_<語言代碼>.json`：該語言的術語詞典；
- `<語言代碼>/translation_schema_<語言代碼>.md`：該語言的翻譯規則與風格約束。

貢獻步驟：

1. 在 `src/prompt_templates/` 下為你的語言建立子目錄，新增術語詞典與翻譯規則檔案；
2. 如需調整全域翻譯行為，修改 `system_prompt_translate_engine.txt`（注意影響所有語言）；
3. 本機測試確認效果；
4. 提交 PR。

---

## 提供人工校對語料

如果你是翻譯模組製作者，並且願意提供你的翻譯語料作為 LLM 翻譯參考，請在 Issue 中發起申請。你需要提供以下資料：

- 你的翻譯模組的 Mod ID 以及翻譯的目標語言；
- 你的翻譯模組的後台頁面截圖，以證明你是模組作者；
- 在 Issue 中明確表示你願意提供翻譯語料；
- 如有特殊情況（特殊授權等），請一併說明；
- 請確保你提供的語料具有較高的品質。

在你的授權下，專案會將你的模組列入 `config/ref_translation_mods.json` 參考翻譯模組列表中，管線會自動同步你的翻譯文字作為 RAG 參考語料。

## 管線與工具開發貢獻

本專案的自動化分為兩部分：

**管線模組（`src/`，C# / .NET 10）**：包含 15 個按序執行的模組，負責從模組下載、文字擷取、內容審查、Embedding 計算、RAG 檢索到 LLM 翻譯與最終輸出的完整流程。詳見 [技術文件](../translation_entry_pipeline_zh-hans.md)。

**輔助指令碼（`.github/`）**：用於 GitHub 的自動化。

若你希望：

* 修復現有管線模組或指令碼中的 Bug；
* 為管線新增功能或新模組；
* 最佳化效能或程式碼結構；
* 改進 prompt 範本或 RAG 策略；

可以按如下步驟：

1. Fork 本倉庫並複製到本機；
2. 基於最新分支建立新分支；
3. 在對應目錄中修改或新增檔案：
   - 管線模組修改 → `src/<模組名>/`；
   - 指令碼修改 → `scripts/`；
   - Prompt 範本修改 → `src/prompt_templates/`；
4. 提交前請盡量：

   * 保持原有程式碼風格；
   * 新增必要的註解；
   * 如有條件，附上簡單的測試或使用說明；
5. 透過 PR 提交修改，並在描述中說明：

   * 改動目的；
   * 可能影響的目錄 / 模組 / 指令碼；
   * 是否涉及破壞性變更。

## 資金支援

專案執行中，由於新增模組、舊模組更新文字內容等，需要持續呼叫 LLM API 進行翻譯。而為了約束 LLM 行為，除了基礎的模組文字外，還需要提供大量的提示詞內容（包括基礎提示詞、翻譯規則、術語表、輸入輸出約束、語義查詢結果等），這些內容會消耗遠超原始文字的 Token。因此，專案需要資金的支援。

如果你願意提供資金支援，請聯絡專案維護者。非常感謝！
