## 2. 我可以如何貢獻？

你可以根據自己的興趣和技能，選擇一種或多種方式參與：

- 提供目標語言的翻譯規則
- 提供目標語言的翻譯術語詞典
- 改進系統的提示詞
- 提供人工校對後的翻譯文本語料
- 改進流水線模組（.NET）與自動化腳本
- 報告問題、提出改進建議（在 Issues 中說明）
- 提供資金支持LLM的調用

下面對主要貢獻場景做一些說明。

## 3. 提供翻譯規則、術語詞典、改進系統提示詞

流水線的提示詞模板位於 `src/prompt_templates/`，結構如下：

- `system_prompt_translate_engine.txt`：全域翻譯引擎系統提示詞（所有語言共用）；
- `<語言代碼>/translation_dictionary_<語言代碼>.json`：該語言的術語詞典；
- `<語言代碼>/translation_schema_<語言代碼>.md`：該語言的翻譯規則與風格約束。

貢獻步驟：

1. 在 `src/prompt_templates/` 下為你的語言建立子目錄，添加術語詞典與翻譯規則檔案；
2. 如需調整全域翻譯行為，修改 `system_prompt_translate_engine.txt`（注意影響所有語言）；
3. 本地測試確認效果；
4. 提交 PR。

---

## 4. 提供人工校對語料

如果你是翻譯模組製作者，並且願意提供你的翻譯語料作為 LLM 翻譯參考，請在 Issue 中發起申請。你需要提供以下資料：

- 你的翻譯模組的 Mod ID 以及翻譯的目標語言；
- 你的翻譯模組的後台頁面截圖，以證明你是模組作者；
- 在 Issue 中明確表示你願意提供翻譯語料；
- 如有特殊情況（特殊授權等），請一併說明；
- 請確保你提供的語料具有較高的質量。

在你的授權下，專案會將你的模組列入 `config/ref_translation_mods.json` 參考翻譯模組列表中，流水線會自動同步你的翻譯文本作為 RAG 參考語料。

## 5. 流水線與工具開發貢獻

本專案的自動化分為兩部分：

**流水線模組（`src/`，C# / .NET 10）**：包含 15 個按序執行的模組，負責從 SteamCMD 初始化、模組下載、文本提取、內容審查、Embedding 計算、RAG 檢索到 LLM 翻譯與最終輸出的完整流程。詳見 [技術參考](../technical_reference/technical_reference_zh-hant.md)。

**輔助腳本（.github/）**：用於 github 的自動化。

若你希望：

* 修復現有流水線模組或腳本中的 Bug；
* 為流水線添加新功能或新模組；
* 優化性能或程式碼結構；
* 改進 prompt 模板或 RAG 策略；

可以按如下步驟：

1. Fork 本倉庫並克隆到本地；
2. 基於最新分支建立新分支；
3. 在對應目錄中修改或新增檔案：
- 流水線模組修改 → `src/<模組名>/`；
- 腳本修改 → `scripts/`；
- Prompt 模板修改 → `src/prompt_templates/`；
4. 提交前請盡量：

* 保持原有程式碼風格；
* 添加必要的註釋；
* 如有條件，附上簡單的測試或使用說明；
5. 通過 PR 提交修改，並在描述中說明：

   * 改动目的；
   * 可能影响的目录 / 模块 / 脚本；
   * 是否涉及破坏性变更。

## 8. 資金支持

專案運行中，由於新增模組、舊模組更新文字內容等，需要持續調用LLM API進行翻譯。而為了約束LLM行為，除了基礎的模組文字外，還需要提供大量的提示詞內容（包括基礎提示詞、翻譯規則、術語表、輸入輸出約束、語意查詢結果等），這些內容會消耗遠超原始文字的詞元。因此，專案需要資金的支持。

如果你願意提供資金支持，請聯繫專案維護者。非常感謝！
